# Source manifest and reproducibility

Pipeline order: **raw data → cleaned table → mapping table → graph/model input**.

`manifests/sources.json` is generated by the opt-in builder from local raw bytes. It records source role, namespace, file/path, release/version, source date, acquisition date, URL, license, SHA-256, availability and reproducibility status. Acquisition dates remain NULL when not recoverable; filesystem modification time is not acquisition evidence. URLs come from existing team metadata/scripts, not a claim that the local file was downloaded from that URL.

| Source | Role / IDs | Version evidence / access / license |
|---|---|---|
| hp.obo | active HPO terms and IS_A; HP | OBO data-version and terms:license; local file required |
| phenotype.hpoa | raw disease-HPO including NOT; ORPHA and external disease IDs | header version; no local license declaration: verify HPO terms before redistribution |
| genes_to_phenotype.txt | reference Gene-HPO; NCBI Gene | current TSV lacks version/date metadata; preserve byte hash and mark release unknown |
| clinical XML | Disease-HPO; ORPHA/HP | JDBOR date/version and Licence; source currently declares CC-BY-4.0 |
| gene XML | Disease-Gene; ORPHA/HGNC/source locus | JDBOR date/version and Licence; source currently declares CC-BY-4.0 |
| alignment XML | future disease xrefs | raw missing; legacy CSV is audit only, not fully reproducible |
| HGNC–NCBI mapping | future registry-backed gene resolution | currently missing; required for unresolved NCBI canonicalization |
| OMIM / DisGeNET | not used in v1 | no direct raw input available; access/license not asserted |

Local inputs are placed under `data/raw/hpo/` and `data/raw/orphanet/`. All real datasets/artifacts remain ignored; never force-add them. Git contains code, documentation, manifest metadata and small synthetic fixtures only. HPOA rows mentioning OMIM are not a direct licensed OMIM dataset, and do not create OMIM disease nodes in this export.

## Build

```bash
.venv/bin/python scripts/build_processed.py --canonical-graph
```

Defaults write `data/processed/graph/` and `manifests/sources.json`. Optional `--seed`, `--validation-fraction`, `--test-fraction`, `--raw-dir`, `--output-dir`, `--manifest` are explicit. Omitting `--canonical-graph` retains the existing flat-raw → runtime JSON behavior. Existing runtime JSON is never overwritten by the canonical branch. QC failure exits nonzero and preserves audit reports for diagnosis.

Real CSVs stay local. Run the same command with a different `--output-dir` and compare `artifact_hashes.json` to check byte reproducibility. No timestamps or absolute local paths enter default graph metadata. `path_base=repository` means repository-relative paths; external test/input roots use raw-directory-relative paths.
